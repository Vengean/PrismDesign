# 插件与 Widget 长时间运行性能排查

2026-11-27，根据“Chrome 开久后无响应”的反馈审查。确认了内存持续累积和重复渲染问题，并完成源码修复及隔离 Chromium 验证。没有取得故障现场的浏览器堆快照，因此这些证据不能单独证明整个 Chrome 无响应的唯一原因。

## 确认的问题与修复

| 问题 | 影响 | 修复 |
| --- | --- | --- |
| CDP 控制台、错误、网络数组仅在输出时 slice，采集端无限追加；未完成请求也未限制 | 浏览器测试持续运行时后台内存不断增长 | 每类最多保留 200 条，每条文本最多 4096 字符，未完成请求最多 256 条；平台内部 HTTP 请求不进入网络证据 |
| CDP 网络响应缓存没有显式预算 | 调试期间额外保留响应内容 | Network 总缓存 8 MiB，单资源 1 MiB，与既有 JSON 检查上限匹配 |
| 浏览器命令缓存按 100 条计数，包括完整截图 | 一组大截图可占用大量后台内存 | 同时按 UTF-16 字符串估算限制在 8 MiB；超大结果正常返回而不缓存，detach/关闭时释放；修复旧绑定异步关闭误删新绑定的竞态 |
| 隐藏的 Widget 仍订阅聊天并渲染进度；后台页面同样持续更新 | 多个预览页叠加消耗 CPU、连接与解析内存 | 关闭面板或页面隐藏时停止面板订阅，恢复时从游标补齐；保留草稿、已加载历史和图片。插件通知所需后台订阅独立保留 |
| 每次进度生成新的下载回调，历史 Markdown memo 失效；Markdown 内图片组件类型重复创建 | 历史 Markdown 重复解析，图片反复下载、解码、创建与回收 Blob URL | 稳定下载回调与 Markdown 组件定义，进度不再重建历史图片；取消完整聊天快照的重复 JSON.stringify 比较 |
| 通知后台每条纯文本/工具进度都串行排队并持久化状态 | 长任务积累存储写入和待处理快照 | 对通知相关字段去重，1000 条纯进度零额外存储写入，最终 @ 和完成通知仍送达 |
| 长期开着的会话持续追加消息和历史运行元数据 | 被动会话内存与 DOM 随使用时间增长 | 被动模式保留最近 200 条，保留历史分页入口和正确游标；用户主动加载的历史不因后台更新被丢弃，清理未关联缓存运行记录 |
| 标注反复创建 ResizeObserver，目标移除后动画循环仍持有节点；检查器缓存持有最后 DOM 节点 | 多余观察器/布局工作，已移除 DOM 子树可能被保留 | 相同目标复用观察器，重新初始化/节点移除时取消；检查结束即释放节点缓存；DOM 观察改为一次描述，避免二次方重复读取 innerText |
| 面板重连计时器未清理，通知发现表保留已关闭标签页 | 长期资源残留 | 卸载清除待重连定时器，关闭标签页删除发现记录，销毁 Widget 清理可见性订阅 |

这里的聊天缓存限制仅影响浏览器内存，不删除平台聊天记录。主动加载大量历史仍会增加界面占用，未引入完整消息虚拟列表。

## 隔离浏览器对比

使用发布包 `20261126075254176-a4572416` 内旧 Widget 对比修复版，在同一 Chromium、相同模拟平台服务、100 条历史 Markdown 和一张工作区图片下测试，不访问实际项目数据。

| 指标 | 旧版 | 修复版 |
| --- | ---: | ---: |
| 初始隐藏时面板聊天连接 | 1 | 0 |
| 20 次进度更新产生的历史图片额外请求 | 20 | 0 |
| 40 次开关后的关闭状态面板聊天连接 | 1 | 0 |
| 整轮历史图片请求总数 | 23 | 1 |
| 草稿保留 | 是 | 是 |
| 回收后 JS 堆：循环前 → 循环后 | 8,150,792 → 8,162,332 字节 | 7,003,328 → 7,354,780 字节 |
| 页面未捕获异常 | 0 | 0 |

修复版每次重新打开会进行一次 HTTP 增量补齐，并建立新的实时连接，关闭后释放。快速连续开关 40 次共建立 41 次连接，结束时无残留面板连接；这与旧版持续保持同一连接的行为不同。堆数据是短时压力测试结果，不是数小时真实故障的复现证明，也不把自然的缓存增长误判为泄漏。

另有自动回归覆盖 1 万轮 CDP 事件采集、未完成请求容量、旧响应淘汰、detach 清理、大截图缓存、1000 条被动消息的历史回查，以及卸载时重连计时器清理。通知回归额外覆盖 1000 条纯进度去重和最终 @ 送达。

## 未开启浏览器测试的静置场景补查

用户进一步反馈：未开启浏览器测试，页面打开一两天也会卡死。CDP 证据与截图缓存属于测试/页面控制链路，不能拿它们单独解释这种情况。

补做无新消息、无工具进度的隔离对比：向同一页面发送 20 帧完全相同的空闲会话快照。旧版仍产生 20 次额外历史图片请求；修复版额外请求为 0。原因包括空闲快照仍进入 React 更新，乐观消息过滤在空列表上产生新数组，历史 Markdown 的回调/组件类型不稳定使图片重挂载。服务端心跳会定期推送快照，因此这条链路不需要浏览器测试，也不需要群里持续发消息。已追加空乐观队列的引用复用；前述稳定 Markdown、图片组件以及隐藏面板停订阅措施覆盖此场景。

补充生命周期回归：8,640 个心跳、模拟推进 20 秒/次，不增加 HTTP 读取、订阅、消息或事件缓存；1,000 次断线重连最多同时存在 1 个订阅，销毁后不再重试。这只是加速的协议/资源生命周期测试，不是实际 Chrome 连续运行 48 小时的证明。无故障现场堆快照，仍不能断言长期卡死只由 Prism 引起。

空闲浏览器对比结果保存在本机 `.sit/browser-idle-verification.json`。本轮仍只构建待发布包，未重启 SIT 或更新用户已经加载的插件/页面。
