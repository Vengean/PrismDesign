# Prism Studio 平台系统与功能设计

状态：设计基线；2026-10-21 环境阶段已验收，2026-10-22 基础对话与 Widget/插件平台会话已开发、待用户验收。接续开发先读 [开发进度与上下文](./development-progress.md)，实现边界见本文后半部分。本文不代表全部功能已上线。

## 1. 产品边界

以项目、需求、发布为三个核心概念。开发者配置项目与成员，编辑者在独立需求环境使用 Agent 修改源码，开发者通过发布完成代码集成与预览。工作空间、容器、服务和会话属于底层资源。

第一版发布包含代码集成、版本冻结、集成预览，不包含生产部署。不再依赖或维护 packages/serve。

## 2. 项目

项目配置包括名称、描述、成员、多代码仓库、Git 凭证引用、模型服务、运行镜像、环境变量、初始化与启动脚本、项目说明、测试命令、测试数据隔离和资源策略。

- 仓库分别配置稳定名称、URL、主干分支；Git 认证在项目级统一配置；目录自动确定为 /workspace/<仓库名称>，不另配工作目录。创建需求时逐仓库固定主干 commit，创建需求分支并放入该需求 workspace。
- 不提供独立服务配置。初始化脚本在首次准备环境时执行，也可手动重跑；统一启动脚本在每次启动环境时执行。两者默认在 /workspace 执行。
- Vue、React、Next.js 等使用项目原有开发服务器，监听 0.0.0.0。
- Bash 脚本统一安装、初始化与启动前后端；多进程脚本需后台启动并等待。平台负责脚本进程组管理、统一日志及退出状态，停止环境时清理全部子进程。
- 不要求用户配置运行端口。运行层探测容器内 HTTP 监听端口，平台分配网关访问地址；多个入口展示可访问应用并自动识别默认预览。各需求容器可使用相同内部端口。SSH 端口由代码服务器决定，仍保留项目级配置。需求环境已接入端口探测和网关分配。
- 项目仅保存当前配置，不保存快照或版本绑定；每次启动/重启读取最新配置。保存配置不会打断正在运行的环境。
- 密钥通过平台凭证引用管理，不注入页面、不返回普通配置接口。
- 提供仓库、模型、安装和启动验证；失败阶段和日志可追踪。

## 3. 项目成员与权限

创建项目时管理成员，创建者始终拥有项目管理权限，平台管理员默认拥有所有项目管理权限，两者无需手动添加，不能在项目内降权或移除。其他未加入项目的用户不可见，链接不构成访问授权。需求与发布继承项目权限。

| 能力 | 查看者 viewer | 编辑者 editor | 开发者/管理员 admin |
| --- | --- | --- | --- |
| 查看项目、需求、发布、预览、聊天摘要和测试结果 | 是 | 是 | 是 |
| 创建需求、调用 Agent、查看源码与 diff、使用需求 IDE | 否 | 是 | 是 |
| 申请合入 | 否 | 是 | 是 |
| 需求交互终端 | 否 | 否 | 是 |
| 创建发布、审批合入、配置与成员管理 | 否 | 否 | 是 |

平台全局 admin 是第一版的开发者身份，可创建项目；后续可增加独立开发者身份。项目权限取创建者、平台管理员和显式成员角色的有效权限；默认管理员不占用手动成员名额。平台管理员身份变更实时生效，项目创建者身份独立保留。

查看者无 VS Code 和任何源码浏览入口或文件接口权限。聊天原始工具输出、源码片段与补丁按代码权限过滤。IDE 的终端、任务与扩展执行能力也必须遵守权限。成员撤销后现有连接和短期凭证失效。发布环境对所有角色禁止 Agent 编辑、可写 IDE 和交互 Shell。

## 4. 需求

创建需求填写标题、目标、验收条件、附件、基础版本。默认使用项目稳定版本，可基于发布创建。首次创建即建立持久会话，启动或重建容器不创建新会话。

流程：保存需求 → 读取当前项目配置与各仓库基础 commit → 创建需求分支 → 创建持久化工作空间 → 安装依赖与初始化数据 → 启动业务服务和 Agent → 健康检查 → 开放预览与 IDE。

环境准备是异步任务，有阶段、耗时、错误和重试；不在长 HTTP 请求中等待容器启动。

需求状态：开发中 developing、待验收 reviewing、待合入 pending_merge、已合入 merged、已关闭 closed。环境状态独立：待准备 pending、准备中 preparing、启动中 starting、运行中 running、已停止 stopped、失败 failed。

工作台包含概览、预览、共享会话、验证、代码、环境日志、合入申请。源码区域只对编辑者与管理员开放。停止环境不丢失工作空间、聊天和测试记录。已合入需求只读，后续修改新建需求。

## 5. 会话与协同

- sessionId：持久化需求会话；clientId：连接端；runId：一次执行；browserBindingId：明确的浏览器目标。
- Widget、插件读取平台数据库中的同一会话，消息显示发起用户。
- 消息先持久化再执行；事件带递增序号，通过 WS/SSE 同步，断线按游标补取并去重。
- 保存 Provider 会话标识；不可恢复时使用历史摘要与当前代码重建上下文。
- 同一工作空间只有一个写执行；Agent、Git 切换、手动 IDE 编辑互斥。测试期间也锁定源码。
- 其他用户看到相同状态，可编辑草稿但不能发送新修改任务；第一版不排队。
- 关闭前端不取消服务端任务；显式取消需鉴权和审计。
- 截图与附件放对象存储，数据库保存索引及归属。工具原始输出必须支持角色过滤。

## 6. 预览与客户端

预览网关统一鉴权、代理容器服务、注入独立 Widget 脚本及 workspaceId/requirementId/sessionId/platformOrigin。无需用户安装 Widget 依赖，不改源码。Widget 使用 Shadow DOM 隔离样式。

每工作空间独立域名，多服务使用独立服务域名或明确路由。兼容资源、HMR WebSocket、HTML 压缩、CSP 与流式响应；无法注入时提示兼容性并保留插件入口。

Widget 提前握手检测插件；用户点击入口时，有插件则打开侧边栏，否则展开 Widget。无响应意味着不可用，不直接等同未安装。侧边栏打开要求真实用户手势。

插件按 tabId → workspaceId → sessionId 绑定，切换标签页展示对应上下文，禁止全局 Agent 地址导致串项目。事件必须携带归属。一个需求多个标签页共享会话，分别保存浏览器绑定。

浏览器测试固定发起标签页，切换页面不转移目标。需要焦点时暂停提示；目标关闭或失效时停止相关浏览器步骤。Widget 可查看测试结果，需要插件能力的测试仅在插件可用并授权后执行。

## 7. 鉴权与运行隔离

- 平台、预览、Agent、Git、日志、文件、IDE、WS 均校验身份和项目操作权限。
- 预览通过一次性授权码换取独立域名 HttpOnly Cookie，不共享平台主 Cookie。
- 插件使用短期、限定工作空间的凭证；标识符不构成授权。凭证撤销与现有连接撤销必须联动。
- 不公开容器端口；所有访问通过网关。脚本以非 root 用户运行，不挂载宿主 Docker socket。
- Git、模型密钥由服务端凭证管理；Agent 不直接推送受保护分支。
- 应用预览只读不等于业务系统只读，需配合测试账号、隔离数据和业务接口控制。
- 各需求及发布不得默认共用可写数据库，按项目提供独立实例、数据库或 Schema，支持初始化与清理。

## 8. 发布

仅项目管理员创建，记录名称、说明、各仓库基础 commit、发布分支和数据环境。只启动业务服务，不启动 Agent。

流程：需求申请 → 固定提交 SHA → 冲突与检查 → 管理员审批 → 串行合入发布分支 → 更新版本清单 → 更新集成预览。

- 批准绑定具体提交；继续修改需重新申请或更新申请并重跑检查。
- 冲突回需求环境解决，发布环境不直接编辑。
- 第一版需求只向一个发布完成合入。
- 多仓库合入非原子，逐仓库记录结果；失败标记部分合入待处理，不伪装成功。
- 发布状态：集成中 integrating、已冻结 frozen、已归档 archived；运行状态独立。
- 冻结保存全部准确 commit，停止接收合入；归档回收计算，保留记录。
- 页面同时显示最新集成版本、实际预览版本和更新结果。
- 发布可查看日志及按角色查看只读代码，禁止可写 IDE、终端、Agent。

## 9. 系统架构与数据

客户端 → 统一访问/预览网关 → 平台 API/任务服务 → 环境编排/Agent 网关 → 需求或发布运行环境。

第一版采用模块化单体 API、独立 Worker、容器运行节点、关系数据库、任务队列与对象存储。

核心实体：Project、ProjectMember、ProjectConfig、Repository、Credential、Requirement、Workspace、RepositoryRef、Runtime、ServiceInstance、Session、Message、Run、RunEvent、Verification、Artifact、Release、MergeRequest、MergeResult、AuditLog。

环境闲置可回收，源码使用持久卷；配置、会话、执行、合入、测试记录不随容器删除。依赖缓存可重建。密钥不进入代码卷。

## 10. 实施计划与验收

1. 项目基础：项目/成员 RBAC、当前配置、多仓库、统一 Git 认证与启动脚本配置入口；测试未授权访问、越权管理和成员撤销。
2. 需求基础：需求、会话、发布元数据，继承项目权限；测试配置覆盖、会话持久化与创建事务。
3. 环境编排：分支/commit、容器、日志、IDE、数据初始化；测试重建保留代码和会话、编辑锁。
4. 预览与协同：网关鉴权、Widget 注入、插件按标签页路由、消息存储及事件补取；测试多用户/多项目隔离。
5. 发布集成：SHA 绑定、审查、合并、预览、冻结、归档；测试合并冲突、部分失败和禁止发布编辑。

第一版暂不做生产部署、公开分享、同工作空间多 Agent 并行、消息排队、跨发布自动同步。

## 12. 需求环境启动与预览（第二批）

- 项目需求卡片提供启动/重试、停止、预览、VS Code 和运行日志。状态每 5 秒刷新，日志每 3 秒刷新。查看者只有预览权限；编辑者和管理员可以操作环境、读取日志与打开 VS Code。
- 每次启动/重启读取当前项目配置。修改配置不影响正在运行的环境，重启后应用新脚本、凭证与 Agent SDK。容器每次启动时重建并复用持久卷，已有源码和需求分支不重置。配置不完整时返回失败原因。
- 每个需求对应 `prism-req-<id>` 容器、`prism-req-code-<id>` 持久卷和 `prism/requirement-<id>` 分支。多个仓库分别放在 `/workspace/<仓库名>`，基于配置的基准分支创建同名需求分支，不自动推送远端。
- 新环境拉取代码后执行初始化脚本（默认最多 30 分钟），成功后保存脚本摘要；重启保留文件、依赖和分支，初始化脚本变化时重新执行，没有变化时跳过；启动脚本每次执行。启动脚本可运行前台服务，多个服务需自行后台启动并使用 `wait` 保持脚本运行。
- 新镜像使用 `project-entrypoint.sh`，旧入口不用于项目模式。启动对应 SDK 的 Agent 服务与 code-server，Agent 不直接发布到宿主机；代码服务通过平台鉴权入口访问。基础平台对话、消息/事件持久化和同需求执行串行已接通；Widget/插件文本聊天已接通；完整写进程锁、浏览器测试路由尚未接通。
- 容器内部自动发现大于 1024 的 TCP 监听端口，排除 8080/8090/9527，支持 IPv4 与 IPv6 本地监听；默认选择最小端口，发现多个端口时提供服务切换。无需用户配置宿主机端口。初始化中和没有监听服务时不显示“运行中”。
- 应用通过内部 8090 代理连接，支持 HTTP/WebSocket；宿主机发布端口只绑定 127.0.0.1。外部访问经平台独立网关端口转发，每个需求、服务与 VS Code 使用不同浏览器 origin，与管理页面隔离，支持根路径资源、SPA 和 HMR。
- 从平台认证接口获取 60 秒单次票据，网关兑换 8 小时 HttpOnly 会话 Cookie 后跳转至无票据 URL；逐请求查询当前项目成员权限，WebSocket 每 30 秒复查权限。禁止跨 origin 请求，不向应用转发平台 Authorization 或网关 Cookie。无权限用户即使得到普通预览地址也不能访问。
- 当前网关为直连 HTTP 开发部署形态，平台与容器引擎须在同一宿主机网络空间；Linux Compose 已使用 host 网络。`PRISM_PREVIEW_HOST` 可覆盖链接主机名，默认跟随 API 请求主机名；`PRISM_PREVIEW_BIND` 控制监听地址。外部网络需允许动态网关端口。生产发布前还需配置独立预览域名、HTTPS 和统一反向代理，不能把此开发形态视为生产网关已交付。
- 容器默认 4 GiB 内存、2 CPU、512 PID，移除 Linux capabilities、禁止提权；Git 保持 TLS 验证，SSH 首次接受主机密钥后保存 known_hosts，不使用旧入口禁用验证的配置。
- 日志合并容器输出、应用、Agent 和 VS Code 日志，限制返回大小并脱敏本需求 Git/模型凭证；不回显启动环境变量。

配置简化迁移：旧版本表每个项目的最新记录迁入 `project_configs`，删除需求与发布的版本引用列和旧版本表，清理未引用的旧凭证；保留项目、成员、需求、发布、会话与源码卷。界面移除配置版本号。

## 13. 基础需求会话与 Agent（2026-10-22）

需求卡片提供对话弹窗；消息、任务、事件入库并按游标轮询增量拉取（当前非 SSE）。同需求活动任务由数据库唯一索引约束，其他编辑者可写草稿但不能并发发送。每轮新建 SDK 客户端，依据数据库最近消息构建有限上下文，执行后清理 SDK 会话；SDK 原生恢复仍待实现。

内部通过 Docker exec 连接容器 Agent 的 HTTP/WS，不公开 Agent 端口。Claude/GLM 支持文本事件和按客户端取消；取消确认后等待真正终态再释放锁。运行任务期间阻止环境启动/停止以及 IDE 网关访问，关闭已连接的 IDE socket；这是访问入口协调，尚不是对 IDE 后台 Shell 等所有写进程的强制文件系统锁。

查看者仅获取协作状态，不回显可能包含源码的消息/工具事件。任务中断且无法确认 Agent 停止时持锁，必须重启环境终止旧任务后继续。平台当前禁用 Agent 浏览器工具；Widget 注入和插件平台聊天已接通，测试/视觉编辑能力仍待后续开发。


## 14. Widget 与插件共享会话（2026-10-22）

预览 HTML 注入独立 Widget bundle；通过同源 `/__prism_platform__` 保留接口读取安全环境信息和数据库会话，不向业务项目安装依赖。Widget/插件共享 PlatformClient，所有聊天请求绑定 sessionId；Chrome 按标签页切换上下文，插件通过内容脚本借用该预览的 Cookie，不共享平台 JWT。平台模式不读取独立 Agent 模式的本地聊天历史。

Widget 与插件握手探测；真实点击 FAB 触发插件侧栏，不可用则展开 Widget。HTML 解压后注入并更新 CSP/缓存头；过大、非 UTF-8 或不支持编码时保留原响应。多服务 Cookie 相互隔离。具体实现边界和手工验收步骤见开发进度文档。


### 需求分支同步（2026-10-22）
需求卡片提供按仓库 Pull / Push，目标固定为 prism/requirement-{需求 ID}，仅编辑/管理成员可用。Pull 只快进，Push 不强推，两者均拒绝脏工作区或不匹配的当前分支，不自动提交和合并主干。Git 操作与 Agent、环境操作互斥，并在操作期间关闭可写 IDE 网关。通过运行容器现有 Token/SSH 凭证访问代码平台；更改凭证需重启需求环境。多仓库分别执行，当前不提供跨仓库原子提交、完整审计或 Git 长任务持久恢复。

Git 同步弹窗现提供本地提交：有未提交修改时显示“提交代码”，要求填写提交说明并明确提交所选仓库全部修改；不会自动推送。后端 commit 与 Pull/Push 共享工作区互斥，状态查询只读，提交前再次检查分支与工作区。
