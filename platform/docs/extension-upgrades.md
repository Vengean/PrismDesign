# Chrome 插件版本与升级

平台的 `/api/extension/release` 返回最新版本、最低支持版本和下载入口。
预览的 `/__prism_platform__/context` 返回同一版本策略及同源下载入口；
复用已有上下文请求，不增加定时 HTTP 版本轮询。

## 点击分流与提醒

Widget 点击只判断插件是否响应本地 PING/PONG，不读取或比较插件版本。检测到插件时由真实点击打开侧边栏；无论插件是否兼容都不自动弹开 Widget。侧边栏明确打开失败，或 250 毫秒内没有插件握手响应时才使用 Widget。页面刷新保持 Widget 收起，不恢复旧的展开状态；没有每 5 秒的存在性轮询，也不会因版本校验主动展开 Widget。

版本校验放在插件内部：

- 低于最低支持版本或版本未知：header 下方悬浮显示必须升级提醒，不能关闭；停止加载交互面板。
- 仍兼容但有新版本：同一位置悬浮提醒并提供 ZIP 链接，不占聊天布局高度，允许关闭。关闭选择按“当前版本 + 目标版本”保存在插件本地；切页、重连、刷新后不重复提醒，更高目标版本会再次显示。
- 当前版或更新版本：不显示提醒，不改变聊天面板挂载层级。
- 未实现本地握手协议的更老插件无法被准确识别。Widget 不再负责兼容提示或强制升级判断。

侧边栏使用 Chrome runtime 的实际清单版本判断，不信任页面传来的安装版本。最低兼容版本仍为 0.7.0，提醒没有服务端 HTTP 版本拦截功能；项目访问继续遵循原鉴权和权限校验。

## 发布步骤

1. 修改 `packages/chrome-ext/package.json` 中的版本，同时保持源码 manifest 一致。
   构建时自动使用 package.json 版本写入输出 manifest，防止两者漂移。
2. 若平台变更破坏旧客户端兼容性，提升
   `platform/src/services/extension-release.ts` 的最低支持版本；兼容改动无需提高最低版本。
3. 正常平台 build/dev:server 会构建插件并生成版本化 ZIP；SIT build 在独立
   staging 中构建插件并把 ZIP 放入同一不可变发布包。不修改运行中的发布文件。
4. ZIP 包根目录包含 manifest.json。升级提示直接链接 ZIP，不提供单独下载页。
   当前是解压安装的插件，不会静默安装或自动覆盖用户本地文件。

平台直接下载地址为 `<平台域名>/api/extension/download`。预览页面使用
`<预览域名>/__prism_platform__/extension/download`，链接由上下文接口自动提供。
下载后解压，在 chrome://extensions 加载或重新加载插件，并刷新预览页面。

普通构建的安装包保存在 `platform/web/public/downloads/`，Web 构建复制到 dist。
API 下载入口以附件方式发送匹配版本的 ZIP；预览入口使用已有 Cookie 和项目权限。
安装包缺失时返回明确的 503，避免 SPA fallback 把 HTML 当成 ZIP 下载。
包构建使用原子重命名；已经开始的下载不受下一次同版本构建影响。

本轮仅更新源码和普通构建产物，未重启或停止 SIT，也没有切换其固定版本。

## 2026-11-27 验证

已在隔离 Chromium 中验证：保存过 Widget 展开状态也不会在刷新时弹开；已安装 0.1.0 模拟插件且平台要求更高版本时仍打开侧边栏，Widget 零闪开；无插件时打开 Widget。升级提醒绝对定位在 header 下方，关闭前后聊天区域位置一致；刷新保持关闭，更高版本重新显示；强制升级没有关闭按钮。独立测试覆盖无版本握手、打开失败、普通升级与强制升级状态变化。

当前插件 0.7.2、Widget 0.3.11；本轮只构建新版包，没有重启 SIT 或替换正在使用的插件。
