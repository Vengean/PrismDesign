## 多人群聊协作（2026-11-06，优先于下方历史摘要）

- editor/admin 在 Agent 执行、取消或环境操作期间均可继续发送消息；用户消息以独立消息 ID / request_id 幂等保存，不再要求每条消息立即创建任务。viewer 仅预览页面，无群聊入口，管理端/预览 HTTP 接口和初始聊天 WebSocket 均拒绝其访问，Widget 脚本返回空内容。
- 服务端按会话持久化未读游标与待确认问题。当前执行结束后读取全部未读用户消息并合并为下一轮上下文，Agent 自主判断执行、澄清、回复或等待；不是逐条 FIFO 执行。生产使用 750ms 合并窗口；浏览器关闭不影响调度，启动时恢复尚未处理消息。
- 保持每个 workspace 单一执行锁。确认取消只消费被取消输入，之后的新消息保留；失败暂停自动处理，断连不确定状态仍需恢复环境确认旧进程终止。恢复后跳过已中断任务并读取后来消息，不自动重启被取消任务。
- Agent 使用正常 Markdown 回复及隐藏 JSON 控制块；服务端移除控制块、校验真实成员 ID、持久化 @ 和待确认问题，显式解决才移除旧问题。该协议复用现有 Agent SDK，不新增模型服务或按关键词决策的队列。

- 内容脚本独立构建为 IIFE，避免与侧栏共享代码后生成 Chrome manifest 内容脚本不支持的 ESM import。

## 已确定的产品规则（不要回退）

1. 核心概念是项目、需求、发布。`packages/serve` 不维护，项目运行自己的 Vue/React/Next 等开发服务器。
2. **没有配置快照/版本概念。** 每个项目仅一份 `project_configs`，保存时覆盖。需求与发布不绑定配置版本。
3. 每次启动/重启需求环境读取项目当前配置。保存配置不打断运行中的环境；需要生效时手动重启。
4. Docker 环境变量不可原地更新，因此每次显式启动会移除旧进程容器并重建，复用源码卷。不要删除卷、重置工作树或丢弃未提交修改。
5. 初始化脚本成功后保存摘要；首次运行或脚本变化时执行，未变化则跳过。启动脚本每次执行，两者工作目录均为 `/workspace`。

8. 不要求用户配置应用端口，平台自动发现和分配。SSH 端口是代码服务器连接端口，仍需配置。
9. Agent SDK 下拉只支持 Claude Agent SDK（默认）和 GLM SDK，项目内配置凭证、地址、模型。没有全局模型供应商管理，也没有单独的“供应商类型”。GLM 沿用现有 `glm-acp-agent` 适配器。
