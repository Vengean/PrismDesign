# 多人盯着一个 Agent 干活，是种什么体验？

## 1. 什么是 Prism Studio？

Prism Studio 是对一种新协作模式的尝试：

**多人围绕同一份源码，指挥一个 Agent，共创一个 Web 应用。**

源码是高信噪比的上下文。组件、样式、业务逻辑和项目规范都在那里，不需要每个人重新向 AI 解释一遍。

产品、设计、开发和测试也不再各自开一个对话框，让不同 AI 重复理解同一个项目。大家共享项目上下文，减少 AI 的碎片化使用，让 Agent 真正成为团队里的共同执行者。

## 2. 和 Vibe Coding 有什么区别？

Vibe Coding 更像是：**我有一个想法，让 AI 帮我实现。**

Prism Studio 更关心：**一个团队如何围绕真实项目，长期和 AI 协作。**

它不追求“一句话生成整个应用”，而是让不同角色基于同一份源码持续补充需求、设计、实现和验证。

简单来说：

- Vibe Coding 偏个人创作
- Prism Studio 偏多人共创
- Vibe Coding 关注“能不能生成”
- Prism Studio 更关注“生成后怎么协作、验证和维护”

## 3. 谁对代码质量负责？代码怎么管理？

还是人负责。

Agent 可以写代码，但不能成为责任人。开发者仍然要设计架构、审查 Diff、处理复杂逻辑，并决定代码是否可以合并。

Prism Studio 直接修改项目源码，因此原有的工程体系依然有效：

- Git 分支隔离不同任务
- Diff 检查每次修改
- Pull Request 完成代码审查
- 测试和 CI 负责质量验证
- 出现问题可以回滚

不是把代码交给 AI 后听天由命，而是让 Agent 进入团队已有的代码管理流程。

## 4. 使用 Prism Studio 后，大家做什么？

产品仍然负责判断做什么、为什么做，以及结果是否解决了问题。

设计师仍然负责体验、视觉和交互，只是可以直接在真实页面上表达意见。

测试仍然负责场景、边界和风险，Agent 可以执行测试，但测试策略不能靠它临场发挥。

开发仍然负责架构、工程质量和复杂实现，还要审查 Agent 写出的代码。

大家不是 Agent 的传话筒。恰恰相反，每个人都要用自己的专业能力告诉它：**什么才算做对了。**

## 5. 这看起来像可视化工具，后台开发也能用吗？

可以。

Prism Studio 从页面进入，是因为真实页面最容易观察、沟通和验证，但 Agent 面对的是整个项目源码，并不只能修改 UI。

它可以处理接口、服务端逻辑、数据结构和其他后台代码。团队还可以通过 MCP 为 Agent 提供受控的数据库能力，用它准备测试数据、构造边界场景，再回到页面验证结果。

当然，生产数据库还是不要让它自由发挥。

## 6. 怎么让 Agent 更高效地干活？

别让每个人都重复教它一遍。

团队可以在项目中统一维护 Skill 和 MCP：

- Skill 告诉 Agent 项目规范、工作流程和最佳实践
- MCP 为 Agent 提供数据库、内部系统及其他工具能力

这些能力跟随项目共享。规则维护一次，所有参与者都能复用，Agent 也不用在每次对话里重新猜测团队习惯。

## 7. Prism Studio 提供了哪些有意思的工具？

目前最有意思的是评论和自动化测试。

### 评论不是在截图上画个框

选择页面元素时，Prism Studio 会结合 DOM 结构和 Source Map，获得组件、源码文件、代码位置等信息，再把评论一起发送给 Agent。

你不必费力描述“右上角第二个灰色按钮”，Agent 可以直接知道你在说谁。

### 自动化测试也不只是替你点几下页面

Playwright 是专业的浏览器自动化框架，适合开发者编写和维护稳定的测试脚本。Prism Studio 并不替代它，而是在更上层提供 Agent 驱动的测试体验：

- 用自然语言描述要验证的目标
- Agent 根据当前页面规划并执行操作
- 自动展示执行过程、耗时和证据
- 测试失败后继续结合源码分析和修改

Playwright 更像一套可靠的测试工具箱；Prism Studio 更像一个能读源码、操作页面、展示证据，还能继续修代码的测试搭档。
